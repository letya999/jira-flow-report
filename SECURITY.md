# Security and data handling

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/letya999/jira-flow-report/security/advisories/new)
when available. If it is unavailable, email the maintainer at **artemletyushev@gmail.com**.
Do not post credentials, real exports or sensitive issue details in public issues.

Include the affected version, a minimal synthetic reproduction, expected behavior and impact.
This is a small maintainer-run project; no response-time SLA is promised.

## What is read and stored

- Live extraction reads Jira Cloud issues, histories, field metadata and project hierarchy.
  It does not change Jira issues. The account's permissions limit what can be retrieved.
- `JIRA_BASE_URL`, `JIRA_EMAIL` and `JIRA_API_TOKEN` come from the environment or a local `.env`.
  Process variables take precedence. Credentials are not accepted in YAML or written to report exports.
- Local `.cache/` and output files contain internal issue and person data.
  The complete project hierarchy may include records outside the flow-metric filters.
- A generated HTML report embeds issue data and metrics. It requires no external scripts,
  font service or analytics; its content security policy blocks network connections.
  Clicking an issue link explicitly opens its Jira URL.

## Sharing and Git

Treat all real reports and snapshots as internal data, even when no token is embedded.
Only `configs/example.yaml` is intended for Git; it contains synthetic settings.
Concrete configs, `.env`, caches and report runs are ignored and rejected by the path guard.
The demo and README screenshots contain fictional data generated by `examples/demo.py`.

Install local hooks after cloning with `git config core.hooksPath .githooks`.
Do not run untrusted configurations or exported files without reviewing their origin.
If a credential is committed or shared, revoke it first; removing a file or rewriting history
does not revoke copies already made.
